# AIGC 内容创作 Agent —— 架构与搭建逻辑（流程图版）

> 配套代码：`E:\手搓Agent`。文字版详解见仓库根目录 `ARCHITECTURE.md`，
> 运行时踩坑与修复记录见 `README.md`。本文只讲**怎么搭的**和**为什么这么搭**。

---

## 一句话概括

这是一个**自己写的 Agent 运行时（harness）+ 长在它上面的内容生产领域层**。
内核不知道"短剧""分镜"是什么，领域层不碰上下文、权限、成本这些事。
两边通过一个 `ToolProvider` 接口相连，所以换赛道只换领域层，内核不动。

---

## 图 1 · 分层与依赖

四层，**依赖严格单向向下**。这条由 import-linter 在 CI 里强制，违反就构建失败。

```mermaid
flowchart TB
    subgraph L3["L3 交互层 interfaces"]
        CLI["CLI：chat / drama / video / assets / rpa / sessions"]
        MCPS["自带 MCP Server：素材库"]
    end

    subgraph L2["L2 领域层 domain —— 懂内容生产"]
        FN["functions：40+ 个工具面<br/>drama / media / files / vision / short_video ..."]
        ASSET["assets：资产库 + 血缘"]
        DRAMA["drama：短剧三段式 + 服装 + 音色 + 一致性 + 规格"]
        PIPE["pipeline：配方 / 剪辑节奏 / 字幕对齐 / 按集流水"]
        QC["compliance 机审 · realism 真实感 · distribution 打包"]
    end

    subgraph L1["L1 能力层 capabilities —— 通用但非内核"]
        SKILL["Skill Hub：方法论热加载"]
        MEM["Memory：滑窗 + 长期记忆 + Brief"]
        MCPH["MCP Hub：外部工具接入"]
        RET["Retrieval：统一检索"]
        SUB["SubAgents：子代理编排"]
        BUD["Capability Budget：能力区预算"]
    end

    subgraph L0["L0 内核层 harness —— 不知道内容是什么"]
        EXEC["Execution：Router + Loop + Graph + Trace"]
        GW["Model Gateway：重试 / 流式 / 计费"]
        CTX["Context：滑窗 + 压缩 + 组装"]
        TOOL["Tool Runtime：注册表 + 分发器 + 两级披露"]
        PERM["Permission Gate + Cost Guard"]
        BUS["Event Bus：所有事情都发事件"]
    end

    L3 --> L2 --> L1 --> L0
    L0 -. "禁止反向依赖" .-> L2
    linkStyle 3 stroke:#d33,stroke-dasharray:4
```

**为什么这么分**：换一个内容赛道（短剧 → 播客），只改 L2；
换一个模型供应商，只改 L0 的 Gateway。两边互不知情。

## 图 2 · 启动时装配什么（`app.py` 的 `create()`）

一次装配，顺序有依赖，不能乱。

```mermaid
flowchart TB
    START(["agent chat 启动"]) --> ENV["加载 .env + 探测代理"]
    ENV --> CFG["读 5 份配置：<br/>models / media_models / drama / hosting / compliance"]
    CFG --> BUS["建 Event Bus<br/>事件流按会话落盘 JSONL"]
    BUS --> TRACE["挂 ExecutionTrace<br/>订阅事件自动建 DAG"]
    BUS --> GUARD["挂 Cost Guard<br/>金额 + 次数两套口径"]
    TRACE --> STORE["建 AssetStore + MemoryStore<br/>+ 产物目录 OutputPrefs"]
    GUARD --> STORE
    STORE --> SKILL["加载 skills/*.md"]
    SKILL --> REG["建 ToolRegistry"]

    REG --> P1["注册内置工具 + 两级披露元工具"]
    P1 --> P2["注册领域工具面（按依赖顺序）：<br/>内容 → 文件 → 托管 → 视觉 → 媒体 → 音频<br/>→ 抖音 → 剪辑 → 热点 → RPA → 短剧 → 检索<br/>→ 合规 → 分发 → 分析 → 子代理 → 逐集写作"]
    P2 --> PIPE["建按集流水管线（/auto 打开后才派活）"]
    PIPE --> MEMA["建 Memory Agent + 会话快照"]
    MEMA --> LOOP["建 LoopRuntime<br/>装 Context 组装器 / 分发器 / 权限闸 / 预算询问器"]
    LOOP --> MCP["setup：连 MCP Server，工具并入同一个注册表"]
    MCP --> READY(["就绪：一个输入框 + 40 多个工具"])
```

**关键判断**：所有工具都注册进**同一个**注册表，MCP 的外部工具也不例外。
权限、成本、事件因此只有一套通路，不会分叉。

## 图 3 · 一轮对话怎么跑（主循环）

这是整个 Agent 的心脏。模型决定下一步，不是流程图决定。

```mermaid
flowchart TB
    IN(["用户输入"]) --> RECALL["按输入召回长期记忆<br/>倒排索引，不调模型"]
    RECALL --> PIN["pin 项目卡 + 记忆简报到注意力最强位"]
    PIN --> TURN["新建 turn"]

    subgraph ITER["迭代（单轮最多 N 次）"]
        ASM["组装上下文<br/>系统区 + 能力区 + 滑窗 + 本轮"] --> FIT{"装得下？"}
        FIT -- 否 --> EVICT["驱逐最旧轮次 → 仍不够则整轮压缩"]
        EVICT --> ASM
        FIT -- 是 --> CALL["调模型"]
        CALL --> ERR{"出错？"}
        ERR -- "连接/超时" --> RETRY["网关重试<br/>连接类更深预算 + 退避 + 抖动"]
        RETRY --> CALL
        ERR -- "上下文超限" --> SHRINK["压缩本轮后重试一次"]
        SHRINK --> ASM
        ERR -- 否 --> WANT{"要调工具吗？"}
        WANT -- 否 --> DONE(["本轮完成"])
        WANT -- 是 --> GATE["工具分发：权限串行 → 执行并发"]
        GATE --> SUSP{"有工具请求人审？"}
        SUSP -- 是 --> HOLD(["挂起，等人决策"])
        SUSP -- 否 --> BUDGET{"超预算？"}
        BUDGET -- 是 --> ASK(["问人追加，或停下"])
        BUDGET -- 否 --> ASM
    end

    TURN --> ASM
    HOLD --> RESUME["人的决策作为该工具的返回值填回"]
    RESUME --> ASM
```

**两个设计点**

- 人审不是流程图上的固定节点，而是**模型自己判断该让人看一眼时调用的一个工具**。
  它会挂起主循环；人的决策作为那次调用的返回值填回去，模型据此接着干。
- 单轮迭代上限是**护栏不是终点**。撞线后可以在同一轮里接着跑，不新开轮次，
  所以"人审前后仍算同一问一答"。

## 图 4 · 上下文怎么进模型

上下文是最稀缺的资源。四个区，各有各的淘汰规则。

```mermaid
flowchart LR
    subgraph WINDOW["送进模型的一次请求"]
        SYS["系统区<br/>角色 + skill 目录 + 项目卡 + 记忆简报<br/>常驻"]
        CAP["能力区<br/>工具目录 30 token/个<br/>+ 按需展开的完整 schema<br/>有预算，超了按 drop→collapse→shrink 降级"]
        HIST["历史区<br/>滑窗保留最近 N 轮<br/>更旧的折叠成摘要"]
        CUR["本轮<br/>工具参数与结果超长时折叠成存根"]
    end

    SYS --> REQ(["一次请求"])
    CAP --> REQ
    HIST --> REQ
    CUR --> REQ
    REQ --> CAL["按真实用量校准估算<br/>下次组装更准"]
    CAL -.-> WINDOW
```

**为什么要做这一层**：一部 60 集短剧，如果每集正文都进上下文，
窗口会从 3 万涨到 25 万 token 直接撞模型上限。
解法是**写作交给无状态子代理**，主循环只收资产 id 和结尾钩子。

## 图 5 · 一次工具调用要过几道闸

```mermaid
flowchart TB
    M(["模型要调工具"]) --> PARSE["解析参数"]
    PARSE --> KNOWN{"工具认识吗"}
    KNOWN -- 否 --> REJ(["拒绝，附相近工具名"])
    KNOWN -- 是 --> LEVEL{"权限等级"}

    LEVEL -- "L-read 只读" --> PASS["放行"]
    LEVEL -- "L-write 可回滚" --> PASS
    LEVEL -- "L-compute 花钱" --> COST{"预算内？"}
    LEVEL -- "L-external 不可逆" --> HUMAN(["强制问人，永不自动放行"])

    COST -- 是 --> PASS
    COST -- 否 --> ASKM(["问人追加金额<br/>钱是最后一道闸"])

    HUMAN --> PASS
    ASKM --> PASS
    PASS --> RUN["并发执行，按工具设超时"]
    RUN --> TRUNC["结果超长按工具上限截断"]
    TRUNC --> BACK(["回填给模型"])
```

**权限串行、执行并发**：问人必须一个一个问，不然终端提示会交错；
真正执行可以几十个并发跑。

## 图 6 · 短剧生产链（主力场景）

六步固定，每步产出一个资产，下一步吃上一步的 id。

```mermaid
flowchart TB
    subgraph W["① 逐集写剧本"]
        WRITE["无状态子代理逐集写<br/>契约只带本集条目 + 角色档案 + 上一集结尾"]
        WCHK{"规格检查<br/>4 分钟字数 · 开场 15 秒高潮点"}
        WRITE --> WCHK
        WCHK -- 不合格 --> WFIX["带问题扩写一次"]
        WFIX --> WCHK
    end

    IDEA(["一句话想法 / 已有剧本"]) --> PLAN["创作方案 + 分集目录 + 角色档案"]
    PLAN --> REVIEW{"唯一一次人审<br/>总集数 / 每集时长 / 面孔 / 语言"}
    REVIEW -- 拍板 --> W
    W --> SB["② 拆分镜脚本<br/>16-24 镜 · 前两镜标高潮点"]
    SB --> LIB["③ 资产库<br/>角色 + 按场景的服装 + 场景 + 道具 + 音色卡"]
    LIB --> SHOT["④ 视频提示词<br/>单段 10-15 秒 · 服装确定性绑定 · 开场段标 hook"]
    SHOT --> REF["⑤ 渲参考图<br/>主形象 → 各场景服装 → 场景道具"]
    REF --> VIDEO["⑥ 渲分镜视频<br/>参考图 + 前序片段 + 音色锚点"]
    VIDEO --> COMPOSE["拼接成片 + 配音 + 字幕"]
    COMPOSE --> CHECK(["view_video 复核"])
```

**并发与依赖**：无前置依赖的镜头全部并发；引用前序片段的、等音色锚点的按依赖排队。
失败的段重跑时**复用已成功的**，不整集重来。

## 图 7 · 四道质量门（都是"生成后校验 + 不合格自动重来"）

这是这套系统里最花力气的部分。每一道都对应一次真实翻车。

```mermaid
flowchart TB
    subgraph G1["① 真实感门（图）"]
        R1["硬约束前置 + 描述清洗"] --> R2["视觉模型打分"]
        R2 --> R3{"够真实但不丑？"}
        R3 -- "磨皮了" --> R4["往有质感的方向重生成"]
        R4 --> R2
        R3 -- "做旧过头" --> R5["往轻里重生成"]
        R5 --> R2
    end

    subgraph G2["② 人物一致性门（图 + 视频）"]
        I1["参考图逐张点名 @图片N"] --> I2["抽帧 + 参考图一起给视觉模型打分"]
        I2 --> I3{"是同一个人吗？"}
        I3 -- 否 --> I4["把差异写进提示词重生成"]
        I4 --> I2
    end

    subgraph G3["③ 字幕门（视频）"]
        S1["提示词最外层禁字幕"] --> S2["抽帧查画面文字"]
        S2 --> S3{"有字幕 / 水印？"}
        S3 -- 是 --> S4["更硬的禁令重生成"]
        S4 --> S2
    end

    GEN(["生成一张图 / 一段视频"]) --> G1
    G1 --> G2
    G2 --> G3
    G3 --> G4["④ 规格门：时长 / 镜头数 / 开场高潮点"]
    G4 --> OK(["合格，进成片"])
    G4 --> BAD(["仍不达标：保留分最高的一版，<br/>结果里明确标出来交人复核"])
```

**共同的设计**：校验失败**不拦生成链路**，只记备注；
都不合格时保留最好的一版并如实报告，不假装成功。

## 图 9 · 资产、血缘与回退

所有产出都是 Asset，带父子关系。这让"回退到某一版重来"成为可能。

```mermaid
flowchart LR
    A["创作方案"] --> B["分集目录"]
    B --> C1["第1集剧本"]
    B --> C2["第2集剧本"]
    C1 --> D["分镜脚本"]
    D --> E["资产库"]
    E --> F["参考图包"]
    C1 --> G["视频提示词"]
    E --> G
    G --> H["分镜视频"]
    F --> H
    H --> I["成片"]

    ROLL(["/rollback 某个 id：作废它与下游，兄弟分支保留"]) -.-> H
```

**执行痕迹**自动从事件流重建成 DAG，`/trace` 看文字版，`/mermaid` 出流程图。

## 图 10 · 搭建顺序的逻辑（为什么是这个顺序）

```mermaid
flowchart TB
    P0["P0 内核最小闭环<br/>Loop + Gateway + Tool Runtime + Context"]
    P1["P1 主链路跑通<br/>工具面 + 资产 + 人审挂起恢复 + 记忆存储"]
    P2["P2 生成能力<br/>图/音/视频 + 异步任务 + 成本闸 + MCP"]
    P3["P3 长上下文的解法<br/>子代理 + 记忆简报 + Skill Hub + 能力预算"]
    P4["P4 闭环<br/>机审 + 待发布包 + 数据回流"]
    P5["P5 规模化<br/>并行扇出 + 项目级预算 + 可观测"]
    P6["P6 真实使用后的加固<br/>上下文控制 + 四道质量门 + 网络韧性 + 本地素材"]

    P0 --> P1 --> P2 --> P3 --> P4 --> P5 --> P6

    N1["早做便宜、晚做很贵：<br/>ToolProvider 接口必须 P0 就定"] -.-> P0
    N2["打回理由补不回来：<br/>记忆存储必须 P1 就有"] -.-> P1
    N3["记忆简报依赖子代理：<br/>子代理提前到 P3"] -.-> P3
    N4["P6 全部来自真实翻车，<br/>不是设计阶段能想到的"] -.-> P6
```

**P6 这一批的由来**（每条都对应一次实际失败）：

| 现象 | 根因 | 处理 |
|---|---|---|
| 生成的脸全是磨皮脸 | 真实感要求挂在提示词末尾被当成可选氛围 | 硬约束前置 + 描述清洗 + 生成后校验 |
| 人物换脸、服装乱变 | 参考图只是"传了"没点名；链接 24 小时失效后等于零参考 | 逐张点名 + 一致性打分重生成 + 链接刷新 |
| 同一角色声音越听越不像 | 每段视频各自发声 | 音色卡 + 音色锚点片段跨集沿用 |
| 画面被烧上字幕 | 模型把台词渲成字幕条 | 最高优先级禁令 + 抽帧检查重生成 |
| 一集 4 段挂 3 段 | 拼接后把远端链接换成本地路径；一次网络错误就判死任务 | 不改 uri + 深度重试 + 只补失败的段 |
| 代理抖一下整轮白做 | 重试只等 1.5 秒；失败即整轮判死 | 连接类深重试 + 同一轮自动续跑 + `/retry` |

## 最后：这套东西的取舍

| 决定 | 代价 | 换来的 |
|---|---|---|
| 自己写 harness 不用现成框架 | 前期慢 | 上下文、成本、权限、痕迹全部可控可改 |
| 流程是数据不是代码（yaml 配方/规格/风格） | 多一层解析 | 调效果不用改 Python，改完重启即生效 |
| 所有产出落资产带血缘 | 存储与代码开销 | 能回退、能对比、能复盘、能归因成本 |
| 质量门都做成"校验 + 自动重来" | 每次多一到两次模型调用 | 不合格的东西不会静默流到成片 |
| 人审只留关键的一次 | 需要提前把话问清楚 | 长剧批量生产不被逐条确认卡住 |
