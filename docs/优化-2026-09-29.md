## 一、出错处理与外部接口

### 1.1 余额耗尽被当成普通错误 〔P0〕
- **现场**：
  - APIMart 余额不足时先回 **500**（`insufficient quota: balance=85356, required=102911`），再回 402。
  - 9-27 两次 `drama_shots` 共重试 12 次，最后 402。每次已出好的 2 批结果被丢掉，原始的 `APIStatusError: Error code: 402 …` 直接抛给了主模型。
  - 媒体侧 `gen_videos` 一批 8 段并发，全部 402。
  - 9-23 连着 20 次 402，被当成模型问题，换了两次模型。
- **证据**：
  - `harness/model/gateway.py:304-306`：500 在 `retry_on` 里，照样重试。
  - `classify_model_error`（`gateway.py:479`）只认 402/403/429，而且只在主循环里用；工具内部拿到的是原始异常。
  - `drama.py:3535` 直接 `raise r`。
  - 媒体的 402 只当成普通的提交失败。
- **改法**：
  - `_with_retry` 看到余额类文本就不再重试。
  - `chat()` 抛 `QuotaExhaustedError`：APIMart 的提示去充值，Kimi 的 403 提示等额度窗口。
  - 同一个 key 的文本和媒体一起熔断。
  - `_run_batch` 和 `render_shots` 遇到第一个 402 就停下整批，原因写在结果最前面。
  - 分批出提示词先把成功的批存下来（见 2.4）。
  - 系统提示词加一句「余额不足不要换模型、不要重试，告诉用户去充值」。
- **拍板**：熔断后怎么恢复。A 充值后下一次调用自动试探，通了就恢复（**推荐**）；B 要你敲命令解除。

### 1.2 视觉门：面容审查从没比对成功过；图片「没查成」记成通过 〔P0〕
- **面容审查**：`drama.py:2186` 把 `base.local or base.url` 当参考图传给 `_check_identity`。`local` 是本地文件路径（`_local_of`，`:2168`），而 `_ref_payload`（`:1624-1631`）只把 `as_…` 开头的 id 和资产库里有的 uri 转成 data URL，路径会被原样返回、当成图片链接发给 Kimi，结果必然 400。`_audit_one` 把这种情况记成「比不了」跳过（`:2193-2195`），所以只要基准图有本地副本（现在这是常态），这个审查就什么都没比。
  - 一直测不出来，是因为 `tests/test_face_audit.py:160` 把 `_image_payload` 换成了假的，假网关（`:146`）也不检查图片链接的格式。
  - **改法（一行）**：传 `base.asset_id`，让它走 `_image_payload` 转成 data URL。另外补一条不替换 payload 构造的测试。
- **远端链接**：`_image_payload`（`:3878-3891`）和 `_ref_payload` 在没有本地副本时退回远端链接；`view_image`（`functions/vision.py:183/188`）也直接发远端链接。Kimi 拉不到 `getapib.org` 的图，9-21 一个会话就报了 8 次 `unsupported image url`。9-22 之前生成的图大多没有本地副本。
- **图片没查成按通过**：`_check_realism` 调用失败时返回「通过」（`:3919-3920`）；`IdentityVerdict.passed` 默认是 True（`drama/identity.py:107`），`_identity_gate_image`（`:3834`）不看 `unchecked`。视频段 9-27 已经改成「没查成 = ⛔」，图片还是按通过记，包里、报告里都写「一致」。
- **改法**：统一一个 `vision_payload()`：
  - 本地文件或路径转成 data URL；
  - http 链接先走代理下载，再转 data URL；
  - 都拿不到就算「没查成」。
  - render_assets 的报告单独列出「没查成 N 张」。
- **拍板**：图片的「没查成」怎么算。A 人物一致没查成的服装图不进包（渲视频时退回主形象），真实感没查成的照样进包、在报告里列出（**推荐**：一致性和视频口径一样；真实感是审美问题，不值得因此拦住整个角色）；B 都进包、只在报告里列出；C 都不进包。

### 1.3 抖音线第一步 6 次 6 次 400 〔P0〕
- **现场**：9-23 的会话里，`short_video_planner` 角色 6 次调用全部 400 `Invalid request Error`，主模型拿着原始 400 连试了 6 次。这个角色从没成功过。
- **证据**：
  - `config/models.yaml:185` 写的是 `thinking_effort: medium`，但 `:136` 的注释写明可选值只有 low / high / max。
  - `gateway.py:194-200` 原样发出 `thinking.effort=medium`，配置加载时不校验取值。
  - 同一个端点上，json + 流式 + low 的 realism_check 成功了一百多次，只有这个角色 400，而且约 100ms 就返回。
  - 结论是**高度怀疑**，没发请求验证。
- **改法**：
  - 改档位。
  - `ModelsConfig.load` 校验 effort 的取值和未知键。
  - 非主角色的 400 包成一条说明错误（写明角色和实际发出的参数，并说明重试无效）。
- **拍板**：A `low`（**推荐**：和其他 json 角色一致，最快最省）；B `high`，要同时把 `max_output_tokens` 从 6000 提到约 12000。

### 1.4 参考图包最后才落库，超时就全部重付 〔P1，渲《不渡》之前要修〕
- **证据**：
  - `drama.py:4309` 到最后才 `store.create` 参考图包。
  - 复用只认上一个包（`take`，`:4107`）。
  - 任务台账只取回**没交付**的任务，已交付的图不会被自动认领。
  - 工具超时是 3600 秒（`:432`）。
- **推算**：9-21 实测 58 张图用了 1843 秒。《不渡》新资产库有 174 张，按这个速度外推要 3000–5500 秒，很可能撞上超时。/stop 也一样。
- **改法**：
  - 每一层渲完、每 N 张就增量落一版包（或者按「这个资产库 + 名字 + 提示词」认领已经生成过的图）。
  - 超时按张数放宽。
  - 不用拍板。

### 1.5 三个小错 〔P1，S〕
- **RPA 抢浏览器目录**：
  - 现象：9-23 同一轮里并发调用 `douyin_hot_rpa` 和 `xhs_collect`，两者共用 `workspace/rpa/profile`。第二个启动时浏览器提示「正在现有的浏览器会话中打开」，随后报 `TargetClosedError`，模型对你说是环境配置问题。
  - 证据：`domain/rpa/browser.py` 没有任何锁；启动失败时（`:124`）也不 stop playwright。
  - 改法：按 profile 加锁（进程内锁 + 跨窗口锁文件）；启动失败时给人话提示并清理。
- **list_voices 列错音色表**：
  - 证据：`domain/generators/catalog.py:227` 的 `render_audio` 列的是 OpenAI 音色、默认 nova，而 TTS 实际走 MiniMax，`has_voice` 查的也是 `speech_voices`。tts 的参数说明写的是「见 list_voices」，于是 9-23 模型照着传了 nova，被拒。
  - 改法：改用 `speech_voices` / `speech_default_voice`，并标出 provider。`harness/model/audio.py:135` 同样要改。
- **素材库拒绝表少两条**：
  - 证据：`interfaces/mcp_servers/material_lib.py:73` 的 `_SENSITIVE` 是照 `domain/functions/files.py:74-87` 手抄的，少了 `**/rpa/profile/**` 和 `.config/gcloud`。MCP 的 `import_material` 因此能把抖音、小红书的浏览器登录态拷进素材库，主进程的 fs_read 再从素材库读出来。
  - 改法：抽成一个没有依赖的小模块，两边共用。

### 1.6 按模型的参数限制没在提交前校验 〔P2〕
- **生图张数**：`functions/media.py:831` 一律允许 n ≤ 4，但 flux-2-pro 只收 1（日志里报过 `n must be 1`）。
- **画幅**：生图不校验画幅，而且目录已经过期——gpt-image-2 只列了 1:1 / 3:2 / 2:3，本地文件证实它出过 16:9 的图。
- **视频**：gen_video 不检查 video_urls ≤ 3；分辨率不对只给警告。
- **改法**：`MediaModel` 加 `max_n` 等字段，在 `_fn_gen_image` 提交前校验。要先按实测把目录修对，再开画幅校验，不然会误拦短剧的 3:4 / 16:9。

### 1.7 gemini provider 全靠缺省值 〔P2〕
- **现状**：`config/models.yaml:90-96` 只配了 url、model 和 300 秒超时。落到缺省值后，retry_on 里包含 500（和 1.1 叠在一起），pricing 为空（见 2.1）。
- **预扣**：APIMart 按 `max_tokens` 预扣。6 次 402 要求的金额都是约 $0.207，正好等于 65536 × 约 $3/百万（输出价）再加上输入，和提示词长短无关。所以余额低于约 $1.2 时，6 批并发就发不出去。
- **改法**：
  - 显式写上 retry 配置；
  - 分批出提示词时按镜头数估 `max_output_tokens`，约 24K 就够。现在单次输出约 1.7 万 token，上限却给到 65536。

### 1.8 开工前自检（doctor）该补的 〔P2〕
- **现在**：`agent doctor`（`interfaces/cli/main.py:728`）只查密钥、有没有配单价、list_models 和 `--cache`。
- **离线能补的**：
  - role_params 的取值和未知键；
  - 各 provider 落到缺省值后实际生效的 retry_on；
  - drama 用的模型和画幅在不在目录里；
  - tts_provider、音色表、默认音色三者对不对得上；
  - RPA 锁。
- **付费探测 `--probe-roles`**：每种「provider × effort × json × 流式」组合发一次最小请求（Kimi 的 max_tokens 要 ≥512），再发一张 1×1 的 data URL 图测看图。实际只花几分钱，能提前抓到 1.3、1.7，还有 9-25 那次「模型没定价」。
- **拍板**：A 付费探测不默认开，手动 `agent doctor --probe-roles`（**推荐**）；B 每次开工都跑。

## 二、钱：看不见的和白花的

> 9-20 以来按参考价计，主循环 430 次调用 ¥68.6。缓存命中率 94%，这部分已经很健康。其余已计价的后台角色合计 ¥15.7（真实感检查 ¥7.05、逐集写作 ¥4.03、看图 ¥2.50、记忆提取 ¥2.11）。

### 2.1 短剧写作（gemini）约 ¥90–100 没进账 〔P1，已知但量级比想的大〕
- **现象**：9-25 到 9-27 三天，gemini-3.8-flash 调用 206 次，输入 374 万 token、输出 369 万 token，`cost=None`。同期账本只记了 ¥24。
- **单价反推**：用余额两次见底之间的变化，加上 1.7 节的预扣金额，反推出输入约 $0.6–0.9/百万、输出约 $2.8–3.0/百万。按此算约 $13–14 ≈ ¥90–100，比主循环还多。开工面板写的却是「金额（含文本模型）」（`interfaces/cli/budget_prompt.py:60`）。
- **改法**：
  1. 你查到单价后填进 `models.yaml`（待拍板·二里已列过）。
  2. 没配价的 provider 按保守估价计入金额，标「估算」，开工面板列出来，不再按 0 算。
  3. 台账把输入、输出 token 分开记，以后补了价能回算。

### 2.2 视频质检每段两次视觉调用 〔P1，渲《不渡》之前做最划算〕
- **证据**：
  - `drama.py:1290` 字幕门、`:1297` 人物一致门各自抽帧、各调一次视觉模型，同样的几帧抽了两遍。
  - 参考图按原图发（`_image_payload`）。
  - 日志里一次一致性判定要 3.8–7.9K token。
- **影响**：《不渡》20 集约 940 段，估算 ¥150–200。
- **改法**：
  - 字幕和人物一致合成一次调用：同一批帧，一份 JSON 里分别给出两个结论，各门的判定口径不变；
  - 参考图缩到 ≤768px。
  - 约省一半，不用拍板。
  - 换更便宜的视觉模型还能再省约八成，但要拍板，建议先不换。

### 2.3 分镜「自动改一次」多数改不好，还整份重出 〔P1〕
- **现象**：drama_storyboard 首次调用 53 次，自动修订了 42 次，其中 23 次改完仍报时长不达标——主要是项目集长还按旧规格。
- **《不渡》现场**：快照仍是 `episode_minutes=20`，`/length auto` 这个项目还没切。现在重拆任何一集，都会被要求补到约 1020 秒（`domain/drama/format.py:388/396`），有凭空加戏的风险。
- **整份重出**：`_revise_once`、`_reparse`（`drama.py:2924/2942`）都是整份重发、整份重出。
- **改法**：
  - 只剩总时长问题时不再自动修订，直接报出差多少；
  - 修订只让模型返回改动的段。
  - **你那边**：在 E:\剧本创作 敲一次 `/length auto`。

### 2.4 分批出提示词：一批失败，全集重付 〔P1〕
- **证据**：`drama.py:3533-3539`：任一批抛异常就 `raise`，任一批报错就 `return []`，已成功的批全部丢掉。日志里因此白付了 21 次调用。
- **改法**：按「批输入指纹」缓存每批结果，重跑只补失败的批。

### 2.5 工具定义约占每次请求的 40% 〔P2〕
- **现状**：
  - 短剧线暴露 66 个工具，估算 12.6K token，实际约 16K（改 system 之后 cached 恰好是 16,384）。
  - 其他产线：抖音 70 个 / 11.5K，广告 60 / 10.2K，设计 44 / 6.9K，不限定 91 / 17K。
  - 5 个《不渡》会话里只用到其中 12 个。
- **最大的几个**（估算 token）：short_video_produce 694、drama_render_shots 686、gen_video 645、compose_video 554、drama_assets 526。
- **改法**：
  - `domain/lines.py:112` 短剧线里的 media / edit / audio / distribution / fanout 改成只上目录、按需展开，约减 5.5K。短剧本来就禁止用 gen_video 补镜头。
  - 删掉工具描述里的「实测记录 / 日期 / 配置路径」，约减 1.5K。
  - 约省主循环 10%，不用拍板。
- **顺带**：`harness/tools/registry.py:161` 按目录顺序把展开的工具插进列表中间，展开一次，这个位置后面的缓存就全部失效。改成追加到末尾。另外 `:145` 满额时 `set.pop()` 收回的是随便哪一个，不是最久没用的。

### 2.6 gemini 输出里估计近一半是推理 〔P2，要拍板〕

## 五、查过、没发现问题的
- **主循环缓存**：命中率 94%。两次掉档都是新一轮的第一次迭代——上一轮刚被折叠，挪到了 pins 之前，这是装配顺序的结构成本，改顺序反而更贵。每轮 pin 的内容合计 1–1.5K token，不随集数增长，放在历史之后，不破坏前缀。统计窗口里工具列表一次都没变过。
- **finish_reason**：drama 各条路径（含 revise / reparse）都查了。截断会报「被截断」，内容被过滤会先软化措辞重试一次。
- **视觉门的帧**：字幕门、view_video、参考视频拆解都用本地抽帧的 data URL。
- **媒体提交与轮询**：
  - 提交遇到 4xx 会退额度，轮询遇到 5xx 会接着问；
  - /stop 或超时的任务进台账，能取回；
  - 视频参考图上限在提交前就校验；
  - 其余工具的超时都有余量：render_shots 实测 1480 秒，超时 7200 秒；drama_shots 实测 303 秒，超时 600 秒。
- **分层和测试隔离**：lint-imports、ruff 都通过；harness 里的领域词只剩注释；测试不连真实网络；workspace 由 conftest 指到临时目录；.env 没被 git 跟踪。
- **启动**：`agent chat` 热启动 import 约 3.5 秒，其中 openai SDK 占 2.4 秒，不值得优化。
